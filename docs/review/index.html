Pre-launch review

An outside opinion on an application you did not write line by line. Ten checks, three ranked priorities, and what it takes to act on them.

01What a review covers

Ten pre-launch checks, the same for everyone, in the same order. The list is public, and you can judge it before we ever speak: the Ship Check 10 checklist.

  • SECRETSKeys in the code — and in the history
  • ENVEnvironment file hygiene
  • ROUTE AUTHAuth on the routes that write
  • DATABASEReachable from the public internet
  • BACKUPSThey exist — and one has been restored
  • UPTIMEHealth endpoint and an outside probe
  • ERRORSMonitoring wired, and watched
  • RATE LIMITINGLimits on auth and public POSTs
  • DEPENDENCIESLockfile and version age
  • COSTA spend guardrail, and who it alerts

Five are verifiable in the code. Five are not — a backup only exists once it has been restored — and those are settled in conversation, not in a form.

02How you send me the code

You run one command on your side and send me the file it produces.

git bundle create app.bundle --all

That is an archive of your repository, history included. You give me no access — not to your accounts, not to your servers, not to your hosting. So there is nothing to revoke afterwards, and nothing to forget to revoke.

The history is not a nicety. A key deleted from the code stays readable in it, which is why the history is where secrets are found. Without it, half the findings do not exist.

If the command gives you trouble, a read-only key on the repository does the job — you revoke it on delivery. The archive is still better: it leaves you nothing to revoke.

03What stays with me afterwards

Nothing. The archive and the working copy are deleted when the report ships, and the report attests to it, on the copy you receive. The clone is detached from your repository the moment it is made: no accidental push is possible from my machine.

No secret value is copied anywhere — only its location. The report generator refuses to build if it finds a key-shaped string in my notes: that is not an intention, it is a lock.

One thing you would not guess, so it is said here: the review is carried out with the help of an AI agent. The repository's contents therefore pass through that provider, on a business account. It is written on the scope page you sign, too.

04The briefs — a plan, never a fix

Each priority ships with an investigation brief: a text you hand to your own AI agent (Claude Code, Cursor…). It investigates your stack — what I cannot see from a copy of the repository — weighs the options, and comes back with a plan costed in effort.

A brief explicitly forbids your agent to change anything. No file created, no command that writes, no call to your systems, no credential reused “just to check”. It produces a plan; you decide; you apply it if you want to.

That plan is your agent's, not mine: I do not run it, I do not review it, and it commits only you. That is the honest counterpart to it running where I chose not to go.
